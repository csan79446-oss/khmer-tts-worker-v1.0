# ---------------------------------------------------------------------------
# WHY THESE TWO LINES EXIST (do not delete them)
#
# The worker takes PyTorch from the NGC base image: torch and torchaudio are
# NVIDIA *pre-release* builds (2.7.0a0+79aa17489c), and since NGC 25.03 the
# image pins them through /etc/pip/constraint.txt.
#
# A specifier that never mentions a pre-release (e.g. VoxCPM's `torch>=2.5.0`)
# lets pip consider only stable candidates whenever it must select from an
# index. Verified against PyPI metadata:
#   * torchaudio 2.7.0  declares `torch==2.7.0`
#   * torchaudio 2.11.0 declares `torch==2.11.0`
# Neither can ever be satisfied by the pinned pre-release build, so pip ends
# the build with `ResolutionImpossible` -> RunPod reports "exit code: 1".
# That is exactly what the removed `pip install torchaudio` step used to do.
#
# Mentioning `a0` here tells pip that pre-releases are acceptable for these two
# packages only, so the torch/torchaudio already installed in the image (which
# match the constraint pin) always win, and pip never tries to download a
# multi-GB stable CUDA stack that would break the container's CUDA ABI.
# ---------------------------------------------------------------------------
torch>=2.5.0a0
torchaudio>=2.5.0a0
